# 专注视图 Focus View

DSH 桌面端的本地插件。解决的问题：助手的长回答里，真正要你注意的东西找不到，中段还混着工具调用和过程噪声。

它做两件事：

1. **注册一个平行会话视图「专注」**（v2，主角）。切过去之后，官方那套「一行行」的渲染完全不再出现，整页变成**每一轮一张结果卡**：状态与标题、一句结论、可展开的信息块、以及点开才看的原始记录。
2. **普通对话视图里的一张折叠重点卡片**（v1，兜底），外加一条**回答格式约定**（固定标题行 + 结论先行 + 不粘日志）。

数据全部来自会话事件与本地提炼，**不额外调用模型**；不写任何新会话事件，不读别的插件的 DOM；除 `react` 外不 require 任何包，没有第三方依赖。

## 切到「专注」视图

刷新页面后，在会话标题栏的视图标签里会多出一个**「专注」**（官方自带的是「对话」「轨迹」）。点它，这个会话就会记住你的选择。

- 视图选择由 DSH 自己持久化：**有效且已注册的持久化选择优先，其次是 `chat`**；不会自动选中第一个注册的视图。
- 官方那套渲染在专注视图下**不渲染**，所以官方行内的一些东西（工具调用卡片、交付物卡片、动作行）也不会出现——需要时切回「对话」即可，两边互不干扰。

## 专注视图里一张卡的结构

```
┌ 总卡 ────────────────────────────────────────────────┐
│ ● 标题（模型给的【本轮】标题 / 退而取结论 / 再退第 N 轮）  [完成] │
│ 一句价值结论（最多两行）                                        │
├ 信息块（收起是叠压一摞，展开是纵向手风琴）────────────────┤
│ ? 需要你确认   2 条   ← 唯一“看完必须动手”的块，永远排第一        │
│ ▤ 关键数据     4 项                                            │
│ ▦ 产出文件     8 个                                            │
│ ◆ 结论建议     3 条                                            │
│ ! 风险提醒     1 条                                            │
├ 原始记录 N 条（点开）──────────────────────────────────┤
└ 22:38 · 12 次工具调用 · 正文 1874 字          [继续追问] ┘
```

**这张卡里没有执行日志**。原先还有一块「执行过程」（工具调用时间线 + 每步的「详情」按钮），用户的要求是
「把这个结果做成一个卡片，**不要他的执行日志**」——于是整块去掉了：工具调用时间线、每一步的「详情」、
对应的字典键与样式全部删除，卡上只留**回答本身**拆出来的东西。日志仍在官方**「轨迹」视图**里，一眼没少。
客户端还留了一道白名单（`BLOCK_ALLOW`）挡旧宿主推来的 `steps` 块，所以刷新页面就能看到效果，不必等重启。
代价要讲清楚：**176 轮里 149 轮只剩 1~2 个信息块，按设计它们不叠、直接铺开**（会叠成一摞的只有 24 轮）。

**状态**由真实事件判定（`turn/end` 的 `reason.kind`）：`completed` → 完成；`aborted` / `interrupted` / `forked` → 中断；`blocked` / `error` / `max-tokens` → 失败；还没结束 → 进行中。**没有 `turn/end` 但后面又开了一轮**，说明这轮被打断了。药丸会带上理由（`中断 · 已中止`），但**理由和状态名同义时只画一遍**——真实卡上出现过「中断 · 已中断」，那是废话。

**「待确认」只留给真的在等你**：有一次没答复的 `approval/asked`（agent 真的卡在那儿等你）。回答里带「需要你确认」段**不算**待确认——那一轮其实已经结束，只是结尾有事要你定；把它标成待确认会让人以为 agent 卡住了。实测本会话 17 轮里 15 轮都有那个段，全都标成待确认等于把状态信号冲淡。这种情况显示成 **`完成 · 待你定 N`**：状态点仍是完成色（这一轮确实结束了），药丸转成琥珀并写明有几件事要你定，同时「需要你确认」块永远排在信息块第一位。

**边界规则**（照设计稿）：非完成态（进行中 / 中断 / 失败 / 真的在等你）不叠、直接铺开；只有 1~2 个信息块也不叠；一个信息块都没有就退化成只剩总卡。

## 信息块的来源

| 块 | 来源 | 说明 |
|---|---|---|
| 状态 | 真实事件 `turn/start` / `turn/end` | 由 `reason.kind` 判定；未结束但在等审批 → 待确认 |
| 产出文件 | 真实事件 `write` / `edit` / `present` 的参数 | 去重后取文件名 + 扩展名 + 父目录 |
| 原始记录 | 真实事件 | 你的提问 + 助手各条文字 + 每次工具调用 + 失败原因 + **最终回答全文** |
| 结论建议 | 本地提炼 | 列表骨架（小标题在第 0 层，子项缩进一层） |
| 风险提醒 | 本地提炼 | 只取模型自己划出的风险小标题底下的条目 |
| 需要你确认 | 本地提炼 | 只取模型自己划出的决策段 |
| 关键数据 | 本地提炼 | 只认「表格里有一格真的是个数字」与 `**键**：值`；值必须匹配「数字 + 可选单位」 |
| ~~执行过程~~ | 真实事件 `tool/call` + `tool/result` | **已从卡片上移除**（用户要求「不要执行日志」）。工具调用照旧被折叠进状态与原始记录；工具名美化、说明过滤这两条规则现在只作用于原始记录里的工具行 |

**原始记录里那几行工具说明只保留两类**：报错（优先用事件里的结构化字段），以及短结果（如 `No files found`）。长结果不留——否则一次 `grep` 就能把投影撑大几十倍。每轮最多留 6 份说明。**短结果里还要挡掉两类零信息量的东西**：①「成功了」这类样板话（`The file … has been updated successfully.` / `已更新`）；②**工具自己的标记语言**（`write` 回的 `<path>…</path> <type>file</type> <content> Updated file </content>`）——那是给模型看的信封，不是给人看的说明。报错必须留，但会把标签剥掉只留里面的文字。这几条都有闸门守着（样板语 0 条、带标记语言 0 条）。说明文字在样式上是**独占一行**的 `<span>`——踩过一个坑：它是行内元素，`margin-top` 不生效，会和工具名粘成 `改文件 · index.js · 完成The file …`。

**工具名会美化**：本地映射表里没有的名字，`mcp__web__browser_click` → `MCP web · browser_click`，`obsidian_move` → `obsidian · move`。原先这条规则服务于「执行过程」块，现在只作用于原始记录里的工具行——**闸门跟着数据源一起搬了**（工具行行首不许是原始 snake_case；只看行首，所以详情里出现的 `mock_target.mjs` 这类文件名不会被误判）。

**原先「执行过程」里那条「连续重复的调用合成一行」也一并删了**：既然时间线不上卡，合并只会在 wire 里多一份没人看的副本。实测本机一轮里同一个 MCP 工具最多连点四次，合并规则曾经省掉 359 行——现在这 359 行连生成都不生成了。

**产出文件会挡掉明显不是交付物的路径**：隐藏文件（`.gitignore`）、`.tmp/`、`node_modules/`、`.git/`、锁文件与日志。实测一轮里卡片会混进 `.gitignore` 和 `.tmp/dbg.mjs`，过滤后「产出文件」从 4 个变成 1 个——剩下的才是真交付物。`dist/` 不挡（打包产物就放那儿）。

**同一个文件不出现两行**：去重用的是「规范化路径的最后两段」这个键（`scripts/a.mjs` 与 `results/a.mjs` 不会合并），而不是拿显示用的路径去比。踩过的坑：同一个文件一次以相对路径、一次以绝对路径出现，而卡片上显示的路径是**截断过的**（带 `…`），拿截断值做后缀比较根本比不中——截图里一眼看到 `mock-target.mjs` 出现三行。现在有一条闸门盯着「同一轮里的重复行应为 0」，并且 `path` 存**完整**路径（截断只发生在渲染时）。

**原始记录**：最近 **8 轮**带完整原文（实测本机 309 条真实回答：中位 1968 字、p99 4916 字、最长 7057 字，所以 8000 字上限**装得下全部真实回答**）；更早的轮次只留提炼结果，折叠行里会明说「这轮较早，只保留提炼结果」。

## 提炼规则（在 14 个会话 / 176 个真实轮次上量过）

改规则前先跑语料（`scripts/fold-view.mjs`），下面这些就是这一轮改出来的东西：

- **关键数据：改过两轮，都是并排跑候选规则 + 打样例决定的**（`scripts/kpi-variants.mjs`）。第一版只要求「表格行 + 值里出现过数字」，抽出来的是 `1 · 止血 → 12:00 评分链路崩了`、`十、上下文预算 → Q29-Q34` 这类**内容表格和目录**；收紧成「值必须匹配数字+可选单位」后命中掉到 2 轮，这时再拿掉「必须恰好两列」的限制，**命中回到 11 轮而样例全是真数据**——`/fast c20 = 27585`、`ef_construction = 64`、`重复副本 = 54`、`0.3.6 = 54942`。结论：真正在过滤噪音的是**值**那条规则，不是列数。之后又补了一条：**纯数字的「键」不算指标名**（`200 = ~0.99+` 这种是表格行标，实测漏进来过），但带点号的版本号要留（`0.3.6 = 54942` 是版本对比，真数据）。三条不变量（键 2~16 字、不带标点、不能是纯整数；值必须是数字+可选单位）现在都由一条回归闸门钉着。
- **标题位永远不放结论行。** 第一版在拿不到契约标题时拿结论行兜底，结果同一句话在标题位和结论行各出现一次——正是这张卡要消灭的重复。现在顺序是：模型的 `【本轮】` 标题 → **本地从你的提问抽第一小句**（24 字上限，并剥掉开头的斜杠命令）→ 「第 N 轮」。改完 161 轮里 141 轮有标题。这条是**把卡片渲染成纯文本读了一遍**才发现的（SSR 断言只证明"渲染没坏"，证明不了"读起来像样"）。
- **需要你确认：只认决策段，命中从 78 轮降到 22 轮**。第一版把正文里任何带问号的句子都算进来，实测抽到的是反问句、代码片段（`? '查看结算'`）和对话里的台词。**注意它不再等于「待确认」状态**：这一段只决定「需要你确认」块和药丸上的「待你定 N」，状态本身由事件决定（见上文）。
- **结论建议里不再出现总卡那句结论**，也**不再把「需要你确认」「风险提醒」的内容抄一遍**：那些有自己的块，同屏重复就是纯噪音——截图里亲眼看到过一轮的结论建议把 4 条待确认原样重复了一遍（同一段的条目现在直接从结论建议的骨架里排除）。三条相关闸门（自重复 / 与总卡重复 / 与别块重复）都为 0。
- **状态信号不能被自己冲淡**：本会话 17 轮里 15 轮都被标成「待确认」，因为我自己的输出格式约定要求每轮结尾写「需要你确认」段，而状态规则又把那个段当成"agent 卡住了"。现在「待确认」只留给真的没答复的审批，其余显示「完成 · 待你定 N」。
- **产出文件曾经重复 8 遍**：先截断再比对写反了（拿未截断的原路径去和已截断的存量比，永远不相等）。
- **风险提醒与「需要你确认」现在共用同一套噪音判断**：代码围栏行（````sql``）、水平分隔线（`---`）、表格分隔行（`|---|---|`）、以及**剥掉 markdown 标记后只剩标点的条目**。这不是理论洁癖——把卡片截图逐张看过去才发现两个真事：一轮的「需要你确认」第一条是个 `---`（模型的分段线），另一轮的围栏第一行被压成了一条孤零零的反引号 `\``，都被当成「要你拍板的事」摆在了最显眼的位置。修法是两个共用小函数（`isMarkdownNoise` / `hasWordChar`），顺手也用在结论建议的骨架和总卡那句结论上（不再有拿分隔线当结论的可能）。**新闸门：没有「字」的条目应为 0**（反例验证过：把这两个函数短路掉，闸门立刻报 5 条并退出码 1）。
- 表格行只取有问题的那一格，不会把一整行 `| a | b | c |` 塞进卡片；行内 markdown（`**强调**`、反引号、链接）一律剥掉再显示。
- 纯段落式回答没有列表可依时，退回「每段第一句」，并跳过表格/代码开头与太短的开场白。

这一轮 **176 轮的分布**（状态：完成 166 / 中断 7 / 失败 2 / 进行中 1 / 待确认 0）：结论建议 166 轮、产出文件 89 轮、需要你确认 33 轮、**关键数据 10 轮**、风险提醒 7 轮；**3 轮一个信息块都没有**（设计稿的 F2 退化路径）。33 轮属于「完成 · 待你定 N」，158 轮有标题。**块数分布：0 块 3 轮 / 1 块 67 轮 / 2 块 82 轮 / 3 块 22 轮 / 4 块 2 轮**——去掉执行过程之后，**149 轮（85%）只剩 1~2 块，按边界规则它们不叠、直接铺开**，会叠成一摞的只有 24 轮。（这些数字会随语料增长而漂移——跑一次 `scripts/fold-view.mjs` 就是当时的实测值。）

投影体积（同一个最大的会话）：v5 **77 KB**，v1 是 32 KB——大出来的部分就是最近 8 轮的正文原文。去掉执行过程这一块让最大投影从 147 KB 降到 77 KB。

**推送代价（量出来的，不是估的）**：14 个会话共 22435 条事件 → 折叠只推 **11260 次更新**（约每 2 条事件一次）。为什么不是"只推几次"：投影的省法只有一层——**无关事件返回同一个 state 引用**（Object.is 闸门），而每一次**已提交**的工具调用/结果、每条助手消息都会真的改变状态，这些都是"进行中"卡片要显示的东西。单次推送是**整份快照**（框架如此，不是本插件选的），所以中位 **40 KB**、最大 **75 KB**（都比带执行过程时降了三分之一）；**单轮最多只有 10 KB**，并且有一条 **24 KB/轮 的成本闸门**盯着——放宽上限时不许悄悄翻倍。按这个量级：一次推送 ≈ 0.6ms 序列化 + 0.6ms 解析 + 几 ms 重渲染，长回合里远低于 1% CPU。

整屏渲染开销（30 轮 / 937 次工具调用，最大那个会话）：默认态 **79 KB HTML / 1347 个元素**，全部展开 80 KB / 1381，连原始记录一起展开 141 KB / 2255。信息块内容和原始记录都是**按需渲染**的（收起时根本不进 DOM），这就是默认态只有最坏情况三分之一的原因。

## 样式：实底白卡（照 `竖版堆叠.html`）

结构照设计稿：**实底卡面 + 发丝边 + 轻投影 + 16px 圆角**，信息块收起时用负边距叠压成一摞（底下再垫两层缩窄的「纸边」），展开后纵向排开。

- **没做成毛玻璃**：这是你选的方向（「完全照 mockup 的实底白卡」）。v1 那张小卡的毛玻璃样式还在，两套前缀不同、互不影响。
- **面与文字全部落在主题 token 上**，所以深色主题自动成立。实测浅色主题下 `bg-layer-1` / `bg-layer-2` / `bg-base` **全是 `#ffffff`**，卡片与页面同色——所以卡的分层靠发丝边 + 投影，卡内分区靠 `color-mix` 掺 4% 文字色（得到 `#f5f5f6`）。
- **状态色只用在圆点、图标、CSS 生成的记号和提醒条底色上；文字一律 `label-primary`。** 实测警示色 `#f59e0b` 当文字在浅色主题下只有 **2.15:1**，读不清。
- **每个 `color-mix` 前面都有一条不含它的兜底声明**（含五个状态药丸各自的兜底底色）；有回归检查专门守这条。
- 用了一个不在公开 token 清单里的 `--dsw-alias-state-business-primary`（进行中的蓝），写法是 `var(…, var(--dsw-alias-brand-primary))`——取不到就退回品牌色，不会变透明。检查器允许这种「带兜底的清单外 token」，只拦没有兜底的。
- **两处有意偏离设计稿**：① 步骤图标底色 `#e79b2c` 配白字只有 **2.15:1**，压深成同色相的 `#b45309`（5.02:1）；② 产出文件那行**不显示文件大小**，改成显示父目录名——大小要在宿主侧读文件系统，那会让插件依赖 `node:fs`（受限宿主里可能整个加载失败），而且折叠时拿到的大小很快就过期。
- `@media (forced-colors: active)` 退回系统色，`@media (prefers-reduced-motion: reduce)` 关掉过渡，按钮和标题行都有 `:focus-visible` 焦点环。样式注入走 `apply` 里的 `ctx.effect`，卸载时移除 `<style>`。

### 用真实 token 取值算出来的结论

从主题包取出真实的浅色/深色取值，自己算 alpha 合成与 WCAG 对比度（文字按 4.5:1，图形按 1.4.11 的 3:1）：

- **深色主题全部达标**，最低的一条是 9.31:1。
- **浅色主题文字全部达标**（标题 18.90、卡内小字 5.34、五个状态药丸 14.98~16.89、主按钮 18.90）。
- **三个浅色主题的图形项不达标，按「非必需图形」处理并留数**：完成圆点 `#22c55e` 对白底 **2.28:1**、待确认圆点 `#f59e0b` **2.15:1**、中断圆点 `#d4d4d4` **1.48:1**。依据是 WCAG 1.4.11 只管「理解内容所必需」的图形，而这三种状态在卡片上同时有文字（14.98~18.90:1），色点只是第二条提示线；而且这就是主题自己的 `success` / `warn` / `idle` 取值，DSH 自带界面同样这么用。
- **五个信息块图标与八种文件图标的白色记号全部 ≥3:1**（3.68~7.58）。

## 交互（能写死在本地的都写成真的）

- **展开 / 收起**：收起态点任意一张卡或底部的「展开 N 个信息块」都会铺开整摞；展开态下每块可单独折叠（纵向手风琴）；块内超出预览条数时出现「还有 N 个 ›」。
- **原始记录**：点开才渲染（收起时不进 DOM——一屏 30 轮的全文留在 DOM 里，与「轻」的目的正相反）。
- **继续追问**：把 `接着第 N 轮（标题）继续：` 填进输入框。用的是官方输入框的公开接口（`InputActions.captureInsertion()` + `insertText()`），**只填不发**；接口取不到时这个按钮整个不渲染，不留死按钮。
- **执行日志不上卡，而且有第二道保险**：宿主那一半不再产出 `steps` 块，客户端还留了一张**块白名单**（`BLOCK_ALLOW = asks / kpi / files / points / risks`），任何不在名单里的块整块丢掉。为什么两道都要：宿主与客户端是两半，**客户端刷新一下就换新，宿主却要整个 DSH 重启才换新**——中间那段时间旧宿主会继续推 `steps` 过来，白名单保证「不要执行日志」刷新后立刻成立。SSR 回归里专门造了一轮「旧宿主推来的执行过程块」：断言它整块消失、同一轮的正文块仍在（丢的是那一块，不是整张卡）。
- **主动不做的**：「暂停」「修复后重试」这类要 agent 干活的按钮，不假装能一键执行。
- **产出文件那一行打不开，这是接口限制、不是偷懒**：全库 README 里 `openFile` 只出现在两处——`ToolCallOwnerProps`（`tool.call.toolview` 的载荷，由 chat 视图把文件路由到右侧 Sidebar 的文本预览，见 `dsh-client-ui-tool/README.zh.md:46,80`）和 `MarkdownDelegateProvider` 的可选回调（`dsh-client-ui-primitives/README.zh.md:93`）。`conversation.view` 的 owner props 只有 `inspectCall` / `viewRequest` / `openView` / `completeViewRequest`（`inspectCall` 原先被「执行过程」每步的「详情」用着，那个按钮随整块删掉之后，本视图的 owner props 一个也没用到），标准 props 里的 `usePanelInfo` 是**面板选中态**、不是文件打开器（`dsh-client-ui-layout/README.zh.md:57`）；要拿到 markdown 那个回调得 `require('@deepseek-ai/dsh-client-ui-primitives')`，而客户端插件禁止 require `@deepseek-ai/*`。所以文件行只显示文件名 + 扩展名 + 父目录，完整路径放在 `title` 里。
- **输入框不会挡住最后一张卡**（这条是从官方样式里读出来的，不是猜的）：输入框座是同一个滚动容器里的 `flex:none` 兄弟节点，活跃期是 `position:sticky;bottom:0`，上方还有一条 36px 的渐隐。滚到底时它回到自己的自然位置，所以最后一轮完整可见；卡片底部留的 40px 正好盖过那条 36px 渐隐。
- 新内容进来时**只在你本来就贴着底部时才自动跟随滚动**，不会把你从正在读的地方拽走。滚动这件事的判断被抽成了一个**纯函数**（`scrollDecision`：自己是滚动容器就拉 `scrollTop`；不是就只在首次、且底部确实在视野外时调一次 `scrollIntoView`），并由渲染回归里的一张 **7 条真源码查表**守着——滚轮那条 bug 的教训正是「只在浏览器里跑的逻辑没人验得到」。
- **滚动容器属于外壳，而且它有两种配置**（从官方源码读出来的，不是猜的）：
  ```
  scrollBody{display:flex;flex-direction:column;overflow-y:auto}     ← 外壳的滚动容器
    └ viewArea{display:flex;flex-direction:column}                   ← 包装层
        └ 本视图 + 输入框座
  ```
  - **活跃期**：`viewArea{flex:1 0 auto;min-height:auto}` —— 包装层随内容长高，**由 `scrollBody` 滚**；
  - **有 composer overlay 时**：`viewArea{flex:1 1 0;min-height:0;overflow:hidden}` —— 包装层被裁切，**必须由视图自己滚**。

  所以本视图的 `flex:1 1 auto;min-height:0;overflow-y:auto` 三件都不能省（官方 chat 视图自己的滚动条也是这个写法），而 `overscroll-behavior` 必须是 `auto`。**我一度想把它「简化」成一个纯静态块——那会在第一种配置下看着没问题、在第二种配置下整页卡死。** 三条 CSS 闸门把这两半都钉住了。

## 不想开 DSH 也能看：`preview.html`

同目录下的 [`preview.html`](preview.html) 是一份**自带脚本的静态预览**：数据是真的（4 轮真实轮次，覆盖「信息块最多（3 块，会叠成一摞）」/「2 块直接铺开」/「完成 · 待你定 N」/「无信息块退化（中断）」四种），配色是 DSH 主题的**真实 token 取值**，样式是插件实际注入的那段 CSS（一字未改）。双击就能在浏览器里打开，两个开关：

- **主题**：深色 / 浅色一键切（一眼看两套主题下都成立）；
- **页面底色**：在「白」（= DSH 浅色主题的实际情况）与「灰 `#f0f0f0`」（= `竖版堆叠.html` 那份 mockup 的做法）之间切——这就是那个一直悬着的决定的对照：卡片的发丝边对**白**页面底只有 1.26:1，对灰页面底就好得多。

它按顺序排了每轮的三种状态：① 默认（**块数 >2 才叠成一摞；只有 1~2 块就直接铺开，说明文字会随块数变**）② 点「展开 N 个信息块」后（纵向手风琴）③ 点开「原始记录 N 条」后。它和真身只差三样：字体回退、外壳的列宽、输入框区域。

## 提示词契约（唯一的 token 成本）

`回答格式约定（优先级高于风格偏好）`，**198 字符**，走稳定前缀、通常命中 KV 缓存：

1. 第一行固定写成 `【本轮】不超过 20 字的标题`，只放标题。
2. 第一段直接回答用户这次的问题本身：先给结论，不复述问题、不铺垫背景，不用「已完成」「整理好了」这类状态句开头。
3. 正文只写结论与必要推理，不整段粘日志；要用户拍板的事单独列成「需要你确认」。

本地会把 `【本轮】…` 这行**剥掉**当卡片标题（所以正文和原始记录里不会留残留）；模型没给就退回结论行，再退回「第 N 轮」。

**这条契约已经在活体上验过**：本会话检查点里第 13 轮的 `title` 是「专注视图已装好在宿主里生效」，而 `answer` 的开头已经是正文（`【本轮】` 那行不在正文里）——契约生效、本地剥离、卡片拿到标题，整条链路通了；语料里已经有 2 轮命中契约标题。

## 已知边界

- **滚轮这条坑记一笔（真被用户报过「专注界面滚轮没法用」）**：外壳把视图和输入框放在**同一个自己会滚动的 flex 纵向容器**里（`[data-conversation-scroll]`：`display:flex;flex-direction:column;overflow-y:auto`）。视图原先写 `height:100%;overflow-y:auto` + `overscroll-behavior:contain`，在那个 flex 容器里 `height:100%` **解不出确定高度**，于是它变成一个「没有可滚内容、却仍是滚动容器」的元素；`contain` 再把滚轮吞掉、不许传给外层——整个界面就滚不动了。现在照**官方 chat 视图自己的滚动条写法**（`min-height:0;flex:auto;overflow-y:auto`）做成滚动子项，并把 `overscroll-behavior` 放回 `auto`：自己能滚就自己滚，滚到头链式交给外壳。两条禁令（**整份样式**里不许出现 `overscroll-behavior:contain`；每个自己造的滚动容器都必须写明 `overscroll-behavior:auto`）已经写进 `scripts/css-check.mjs`，并用旧规则做过反向验证（喂旧规则会同时命中）。
- **提炼是启发式的**：回答写得散，卡片也散。所以输出契约才是根治的另一半——「结论提取」只有在模型结论先行时才准，这是个正反馈。
- **原始记录只带最近 8 轮的全文**（8000 字上限）。看更早的全文要切回「对话」视图。真要做到任意轮次都一字不漏，需要再加一条「按需向宿主取该轮全量日志」的通道（宿主侧 `ctx.sessions.get(id).snapshotEvents()` 能做到，属于后续版本）。
- **不显示文件大小**、**产出文件不可点开**，原因见上文，都是为了不引依赖、不猜接口。
- **卡片不显示 = 静默失败**：投影值取不到时组件返回 `null` / 空态，不报错。排查顺序：① `Slots.listSubTree` 查 `conversation.view` 的 occupants 里有没有 `id: focus`；② 读 `session_projcache` 里有没有 `focusView` 这个键、`ver` 是不是 5；③ 刷新页面之后新的客户端代码才在页面上（宿主半则要重启）。
- **改 state 字段或折叠语义必须递增 `stateVersion`**（v1 = 4，v2 = **5**：v2 = 工具名美化 + 产出文件过滤，v3 = 产出文件改存去重键 `key` 与完整路径，v4 = 工具名美化扩到 snake_case + 说明挡掉标记语言，v5 = **去掉「执行过程」块**（纯 wire 改动，递增只为让「宿主落后」能被 `verify-view.mjs` 检测到，见上文）；`callId`/标题兜底/结论建议的过滤/原始记录不变的规则只改 `wire.view` 所以不算），否则同名旧检查点会喂进错误的状态形状；**只改 `wire.view` 里的提炼规则不需要递增**——检查点存的是 state，视图由 state 现算。
- **依赖 `turn/start` 事件划定轮次边界**：循环在每轮提示之前必定先记 `turn/start`，所以「挂在最新轮次上」是安全的；重试用同一个轮次号重发 `turn/start` 时保持已有条目不动。
- 本机 `ui-chat.transcriptView` 当前是 `standard`：Chat 自带的「工作详情」在那档已经会折叠已完成轮次的过程，但它不会把重点提到最上面——那正是这个视图补的位置。
