# 重点卡片 Focus Brief

DSH 桌面端的本地插件。解决的问题：助手的长回答里，真正要你注意的东西找不到，中段还混着工具调用、过程噪声。

插件在**每一轮回答的下方**加一张折叠卡片：

- **最上面一行是结论**（回答的第一个段落，压成一行）
- 展开后是一棵**树状要点**（按原文列表的缩进还原层级）
- **「需要你确认」**：正文里带问号的句子单独挑出来
- **「你问的」**：把你这一轮的问题贴在卡片里，方便对照它到底答了没有
- 底部一行过程计数：本轮几次工具调用、正文多少字

同时通过系统提示追加一条回答格式约定：第一段必须直接回答你的问题、结论先行、禁止把工具输出和日志原文粘进正文。

## 三层机制

| 层 | 位置 | 做什么 | token |
|---|---|---|---|
| 宿主投影 | `index.js` → `ctx.sessionProjections.register` | 把会话日志按轮次折叠成 `focusBrief` 投影键 | **零** |
| 客户端卡片 | `client.js` → `conversation.chat.turnTail` 座位 | 读 `useProjection('focusBrief')` 渲染卡片 | **零** |
| 输出契约 | `index.js` → `ctx.systemPrompt.section` | 让模型结论先行、不贴日志、不用状态句开头 | 每次请求 +188 字符（稳定前缀，通常命中 KV 缓存） |

卡片是**纯新增**座位，不替换 DSH 自带的任何渲染；不写任何新会话事件，不读别的插件的 DOM。除 `react` 外不 require 任何包，没有第三方依赖。

## 安装

```
plugin_manager { action: "install_bundle", target: "<本目录绝对路径>" }
```

官方的 `install_bundle` 会自己完成包安装、bundle 注册和 patch 挂载 —— **不要**手改 profile 的 `package.json` 或 `cordis.patch.yml`。

## 提炼规则（在 177 个真实轮次上测过）

- **哪条消息算这一轮的回答**：本轮最后一条**非空**助手消息。实测这就是最长的那条、也就是最终回答（1787 / 1436 / 1558 字），中间那些都是 50–300 字的进度短句。
- **结论**：第一个「够长」（≥12 字符）的非标题段落。跳过 `## 本轮进展` 这类纯标题段落，也跳过「整理完了。」这类状态句；都够短时退回第一个正文段、再退回第一个标题。实测中位 47 字符、最短 13 字符。
- **要点树**：小标题在第 0 层，其下的列表项在第 1 层，缩进再叠一层；混在同一层的假树是修过的 bug。
- **纯段落式回答**（既没列表也没小标题）：退回「每段第一句」当骨架，最多 6 条。实测这类占 14%，退回后要点覆盖率达到 **100%**。
- **需要你确认**：两个来源合起来——① 模型自己用小标题划出的决策段（`## 需要你拍板的`、`## 请你回答这五个问题`），段里的列表项和正文行都算；② 正文里带问号的非列表行。最多 4 条。实测覆盖率 **44% → 47%**，净新增 10 轮原本被整个漏掉的决策点（就是「GitHub fork 用哪个账号」「走方案 A 还是 B」这类）。
  - 为什么不扫关键词：试过「建议/推荐」（命中 28%）和「要不要」（21%），抽样一看全是解释性文字（"这就是…的来源"、表格里的"（推荐）"、环境规格里的"建议 4G+"）——加进去等于制造新噪声。
  - 表格行只取有问题的那一格，不会把一整行 `| a | b | c |` 塞进卡片。
- 行内 markdown（`**强调**`、反引号、链接）一律剥掉再显示。结论行里冒出字面 `##` 是修过的 bug。

## 样式：苹果式毛玻璃

视觉上由五件东西共同撑起——**半透明底 + 顶部渐隐光泽 + 发丝边 + 顶部内高光 + 柔和投影**，配 14px 圆角。

- **只靠 `backdrop-filter` 是不够的**：卡片在正文流里、背后是纯色背景，模糊一块纯色几乎看不出效果。玻璃感主要来自上面那几件的配合，模糊只是锦上添花。
- **语义色全部从主题 token 派生**（用 `color-mix` 造透明度），深浅色主题自动跟随；token 日后改名最多让观感退化，不会把渲染弄坏。用到的 8 个 token 都对着实时主题名单校验过。
- 唯一的字面色是投影里的中性黑 `rgba(0,0,0,.10)`：阴影不是语义色，两种主题下都成立。
- **渐进增强**：每个用 `color-mix` 的属性都先有一条不含它的兜底声明；模糊单独放在 `@supports (backdrop-filter:…)` 分支里，不和上面的属性互相覆盖。引擎不支持时自动退回不透明外观。
- **`@media (forced-colors: active)`** 退回系统色并去掉模糊与投影；**`@media (prefers-reduced-motion: reduce)`** 关掉过渡；按钮有 `:focus-visible` 焦点环。
- 样式注入走 `apply` 里的 `ctx.effect`，卸载时移除 `<style>` 标签（这条路径有测试覆盖）。
- 「待定 N」是一个警示色药丸；「重点」徽章是品牌色半透明药丸。

### 用真实 token 取值算出来的三个结论

从主题包里取出真实的浅色/深色取值（浅色 `bg-layer-1 = #ffffff`、`border-l2 = #0000001a`；深色 `bg-layer-1 = #232324`、`border-l2 = #ffffff1f`），自己算 alpha 合成后的颜色与 WCAG 对比度：

- **浅色主题下卡片原本是看不见的**：`bg-layer-1` 与页面底同为 `#ffffff`，两者亮度差 **0%**。现在往底色里掺 8% 的 `label` 色，卡片底变成 `#f1f1f2`，与页面差 **11.8%** 亮度——这才是一块能看见的玻璃。
- **发丝边被我削过头了**：`border-l1` 本身就是带 alpha 的发丝边（浅 `#0000000a` 3.9%、深 `#ffffff0f` 5.9%），我又用 `color-mix` 按 70% 削一遍，等于把它削到几乎消失。现在直接用 `border-l2` 自带的 alpha。
- **一个只在浅色主题暴露的可读性 bug**：警示色 `#f59e0b` 当文字用时，浅色下只有 **2.15:1**（深色下 7.66:1 没问题），而它当时正是「待定」和「需要你确认」条目的文字色。现在文字一律用 `label-primary`，警示色改由前面那个圆点承担（装饰性，不承担文字对比度）。

改后两种主题 × 6 组「文字/底色」对比度全部达标（浅色 16.77 / 5.15 / 15.47…，深色 13.45 / 9.33 / 10.78…）。

### 运行时确认与真解析

- **运行时是 Electron 44.0.0**（`D:\DSH\version` 里那个 44.0.0；主程序 FileVersion 是 0.2.0-rc.2）：`color-mix`（Chromium 111+）和 `backdrop-filter`（Chromium 76+）都远在其支持范围内，所以**毛玻璃是真生效**，不会走兜底分支。
- 样式经过**真解析器**（css-tree 2.3）严格模式解析：29 条规则 / 4 条 at-rule / 106 条声明，无语法错误；lexer 另外校验了 69 条不含 `var()` 的声明值。
  - `forced-colors` 块里的 `Canvas` / `CanvasText` 会被 css-tree 报"值不合法"，那是它没收录 CSS Color 4 的系统色关键字 —— **误报**：DSH 自己的样式就用这组关键字（`border: 2px solid color-mix(in srgb, CanvasText 25%, transparent)`），已作为豁免写进检查器。
- 四道样式/渲染检查（真解析、token 与兜底、对比度、712 次真渲染）都可单独重跑，退出码 0 才算过。

## 验收（重启桌面端后照着看）

> **样式改动只要刷新页面就生效**（客户端半走 HTTP 取）；**宿主半的改动需要完全重启**（Node 进程里加载的模块代）。

1. 打开任意一个有历史回答的会话，**每一轮回答的下方**应出现一张圆角卡片。
2. 卡片第一行是**结论**（不是一个 `##` 标题，也不是「整理完了。」这种状态句）。折叠时右边还有两个小计数，例如「要点 3　待定 2」——**看到警示色的「待定」就说明这轮有事要你拍板**；最右边是 ▸ 按钮。
3. 点 ▸ 展开：应看到「你问的」「要点」（小标题在第 0 层、它的子项缩进一层）、可能有「需要你确认」、底部一行「本轮 N 次工具调用 · 正文 M 字」。
4. 卡片**排在自带「变更文件」卡片之前**；DSH 自带的其它渲染（正文、工具卡片、动作行）都还在，一点没变。
5. 系统提示层同时生效：模型的第一段应该开始直接回答你的问题。**这一步只影响新产生的回答**，历史回答不变。

## 已知边界

- **提炼是启发式的**：它写得散，卡片也散。所以同时加输出契约才是根治的另一半——A 的「结论提取」只有在模型结论先行时才准，这是个正反馈。
- **它就是"便宜版"**：只做加法，不能把普通视图里的工具卡片、日志整个隐藏——那需要注册一个平行的 `conversation.view` 新视图自己写渲染（后续版本）。
- **卡片不显示 = 静默失败**：投影值取不到时组件返回 `null`，不报错。排查时先看座位是否注册（`Slots.listSubTree` 查 `conversation.chat.turnTail`）。
- **依赖 `turn/start` 事件划定轮次边界**：循环在每轮提示之前必定先记 `turn/start`（`turnOutline` 包的注释明确写了这个不变式），所以"挂在最新轮次上"是安全的。
- **改 state 字段或折叠语义必须递增 `stateVersion`**（现为 4），否则同名旧检查点会喂进错误的状态形状；**只改 `wire.view` 里的提炼规则**（结论/要点/待确认怎么算）**不需要递增**——检查点存的是 state，视图是由 state 现算出来的。
- **本机 `ui-chat.transcriptView` 当前是 `standard`**：Chat 自带的「工作详情」在那档已经会折叠已完成轮次的过程，但它不会把重点提到最上面——那是这张卡片补的位置。
